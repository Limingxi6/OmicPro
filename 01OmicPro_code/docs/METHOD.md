# Method: OmicPro

## Problem Formulation

OmicPro addresses phenotype prediction from partially observed multi-omics profiles. For each sample, the model receives up to three omics modalities: genomics (`G`), transcriptomics (`T`), and metabolomics (`M`). The goal is to predict a quantitative phenotype target such as `yd`, `tp`, `gn`, or `kgw` while remaining robust when one or more modalities are missing.

Let `x_G`, `x_T`, and `x_M` denote the three modality feature vectors. Missingness is encoded by a three-bit code `c`, where each bit indicates whether a modality is unavailable. The model keeps the token order `[G, T, M]` fixed for every sample. When a modality is missing, its raw input is replaced by a zero-filled placeholder, and the corresponding token position is retained in the latent sequence.

## Overall Architecture

The forward path is:

```text
Multi-omics inputs
  -> modality-specific Mamba encoders
  -> fixed G/T/M modality tokens
  -> missing-aware prompt-enhanced fusion
  -> prompt-gated residual update
  -> SummaryResidualAttention fusion
  -> MLP phenotype prediction head
```

OmicPro therefore separates three tasks: extracting modality-specific representations, compensating missing modality positions in latent space, and fusing the enhanced modality tokens for final regression.

## Modality Encoders

Each modality is processed by an independent `MambaOmicsExtractor`. The extractor applies sparse feature reweighting, stacked Mamba sequence blocks, and a projection layer to produce a fixed-dimensional embedding. Given an input vector `x` with feature dimension `F`, the extractor reshapes it as a length-`F` sequence with one channel, applies sparse reweighting, models feature dependencies with Mamba blocks, and projects the result to an embedding dimension `D`.

The three encoder outputs form the fixed token sequence:

```text
Z = [z_G, z_T, z_M] in R^{3 x D}
```

For a missing modality, the corresponding encoder receives the configured missing-fill vector, typically zeros, so the token position exists but initially contains limited information.

## Missing-Aware Prompt Learner

The prompt learner maps the missingness code `c` to learnable prompt tokens. It produces:

- Staged prompts: pattern-specific prompts indexed by the current missingness code.
- Common prompts: shared prompts that provide stable context for each missingness pattern.
- Dynamic prompts: sample-dependent prompts generated by attention over the current modality tokens at the first prompted block.
- Correlation prompts: deeper prompts generated by projecting previous staged/common prompt states through LayerNorm and MLP layers.

At the first prompted block, the token sequence is assembled as:

```text
[staged prompt | common prompt | dynamic prompt | G token | T token | M token]
```

In deeper blocks, generated correlation prompts are inserted before the modality tokens while preserving the fixed G/T/M token positions.

## Prompt-Guided Missing Modality Compensation

Prompt tokens participate in self-attention with the modality tokens. For a sample where transcriptomics is missing, the sequence contains:

```text
[Prompt tokens | G token | T missing placeholder | M token]
```

During self-attention, observed modality tokens and prompt tokens serve as contextual keys and values. The missing placeholder can therefore receive cross-modal and missing-pattern-specific information in latent space, producing a compensated modality representation without reconstructing the raw missing omics vector.

## Prompt-Gated Residual Update

OmicPro does not directly replace original modality embeddings with prompted outputs. It applies a residual gated update:

```text
EnhancedTokens = OriginalTokens + Gate(c) * (PromptUpdatedTokens - OriginalTokens)
```

The gate can be learned globally or per modality and can include missing-pattern-dependent deltas. This lets the model apply stronger prompt compensation to missing token positions while using smaller updates for observed modalities.

## SummaryResidualAttention Fusion

After prompt compensation, the enhanced modality tokens are passed to `ResidualSummaryAttention`. This module uses a learnable multi-head summary query to aggregate the three modality tokens into a compact context vector. The context vector is projected back to the concatenated modality space and added through a fusion gate:

```text
FusedBase = concat(enhanced_G, enhanced_T, enhanced_M)
FusedFinal = FusedBase + FusionGate(FusedBase) * ContextProjection(ContextVector)
```

The fused representation is normalized and passed to an MLP regression head.

## Training Objective

The main loss is mean squared error on the phenotype target. During training, auxiliary single-modality heads are attached to the raw modality encoder outputs. The total objective is:

```text
TotalLoss = MainLoss + w_G * Loss_G + w_T * Loss_T + w_M * Loss_M
```

The auxiliary losses regularize modality encoders and encourage each modality representation to remain predictive. They are used only for optimization; inference uses the fused prediction head.

## Missing-Modality Simulation

Training and evaluation support explicit missingness configurations. Missing codes can be generated by global missing ratios, per-modality ratios, or mixed pattern probabilities. The same fixed G/T/M token order is used for complete, single-missing, dual-missing, and all-missing settings. Missing inputs are filled according to the configured strategy, with zero fill as the default.

## Cross-Validation and Evaluation

The pipeline supports fixed 10-fold cross-validation using `CVFs.csv`. Preprocessing is fitted within each training fold only, then applied to validation and test folds to avoid leakage. Reported metrics include Pearson correlation, RMSE, and R2 for each phenotype target.

## Implementation Notes

The core implementation is in `omicpro/model.py`. The main model class is `MultiOmicsMultiTaskRegressor`. Training is driven by `omicpro/train_cv.py`, and fixed-split evaluation is driven by `omicpro/evaluate_fixed_split.py`.
